# History Correction-Chain Spike Inventory

## Runnable surface

- `run.R` contains nine synthetic trading-status shapes.
- Accepted shapes traverse the exported constructor, validator, snapshot,
  experiment, run and availability-result APIs.
- Constructor-refused shapes use the private prepared status resolver only to
  show what the current runtime algorithm would do if those rows reached it.
- Every shape also reaches the current private ingest conflict classifier.

The private reads are observations, not proposed APIs. Public
`ledgr_facts_resolve()` supports membership and sessions, not trading status,
so it cannot answer this spike's question.

## Gut

The sole gut removes supersession edges immediately before private resolution.
It changes the recorded timeline and falsifies derived observations. The
checker rejects it. No package function is mocked or modified.

## Demoted or deleted

- No second fact model, chain registry or vendor fixture was added.
- No expected policy table was written before the runnable core produced the
  observed CSVs.
- H1's two-capture absence remains negative prevalence evidence; it is not a
  reason to infer correction semantics.
- The earlier stage-1 probes remain historical inputs. This spike replaces
  neither them nor their register rows; it supplies the missing systematic
  constructor-seal-run comparison.

## Learned about the package

- Direct replacements, including partial and overextended intervals, construct,
  seal and run.
- A monotone three-link chain is rejected by the constructor even though the
  prepared resolver yields one state at every cutoff.
- Missing middle knowledge, competing descendants and a mixed chain/fork can
  produce `conflicting` inside the prepared resolver.
- A partial replacement revives its predecessor after the replacement ends.
  The ingest classifier reports no conflict because it shortens the
  predecessor at the successor's start for its own overlap calculation.
- Dangling references and cycles fail closed at construction.
