# RFC: Core Extension Architecture (v0.2.3), Response Review

- Stage: response review (stage 4), maintainer, 2026-11-04.
- Read: the [response](rfc_core_extension_architecture_v0_2_3_response.md)
  (Codex, Type 2, REVISE) with the Claude-drafted brief that produced it.

## Decision

The maintainer accepts the response's framing. Seed v2 is written on its
terms:

- the question becomes which boundaries stay fixed and what is the smallest
  coherent change that adds a contracted capability through the one fold,
  replacing the seed's "one place" promise with an affected-owner map;
- P3 keeps one stage with helpers; no stage registry;
- the OMS synthesis clauses that conflict with later accepted rules are
  reconciled in this cycle, before code;
- cash stays scalar; accounting shares signed-book primitives with named
  owners for new economic rules; intra-bar triggers need their own timing
  contract;
- autonomous events, protective-order parameters and external execution truth
  join the extension scenarios.

The response also recommends narrowing skeleton decision D1. That changes a
maintainer decision, so seed v2 proposes it and the maintainer decides it at
synthesis acceptance.
