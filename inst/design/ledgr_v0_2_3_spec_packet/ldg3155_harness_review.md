## Findings, ranked by severity

**F1 — High: required evidence can disappear and the gate still passes.** `dev/bench/timing/check.R:47-55,85-92,101-103` requires the existence of `host.csv` and `plan.csv`, but never reads the saved plan and never establishes host-snapshot coverage. An empty host file with its header, one missing pre-slot probe, and an empty saved plan each independently produced exit **0 / CHECK PASS**. Missing observations therefore become apparent evidence of no host violations. Required change: validate both schemas; compare the saved plan with the protocol's complete plan and each raw slot's assignment; require the before/after snapshots and exactly one pre-slot snapshot for every executed slot of a complete attempt, with valid timestamps and the session root identity. Reject missing, duplicate and unexpected snapshots/slots. Add negative demonstrations alongside the passing controls. This does not make CPU load a rejection criterion.

**F2 — High: the affinity proof need not identify the measured process.** `host.R:82-89` only finds the root somewhere in the supplied chain; `check.R:129-140` never binds the chain's first entry to `raw$pid`, `raw$created` and `raw$affinity`. A row with affinity **16777215** and a chain containing only the correctly pinned root passes (exit **0**). A contradictory raw affinity and a chain naming an entirely different child also pass separately. The OS timestamps used for order can consequently describe different processes from those whose affinity was checked. Required change: require the first chain entry to equal the row's PID plus creation time, require its affinity to equal the raw affinity and 65535, and validate process identities/epochs before using them for order. Root snapshots must similarly begin with the session root. Keep legitimate PID reuse with a different creation time distinguishable. Demonstrate rejection of all three contradictions.

**F3 — High: execution reads mutable inputs after the cleanliness claim and protocol copy.** `runner.R:114-128,169-175` copies the protocol and samples cleanliness once, but launches every child against the original protocol directory and live `measure.R`; `measure.R:20-21,48-54` then reads live helpers/workloads. A concurrent edit during a window followed by restoration before checking can produce a clean-looking, mixed-input record whose saved protocol never executed. This risk is concrete in this workstream: the retained attempt-2 disposition records runner editing during attempt-1. Narrowing the clean paths in 0e895720 correctly excludes generated records, but does not freeze execution inputs. Required change: freeze the six harness execution files and four protocol files before the window, verify their correspondence to the recorded clean commit, and execute those frozen inputs (including the saved protocol), with a final integrity/commit check invalidating departures. Preserve the failed attempt. Demonstrate an original-file change during a smoke window cannot silently change later slots' executed code. No hash registry or general provenance framework is requested.

**F4 — Medium: attempt allocation can reuse an existing attempt directory.** `runner.R:69-75,114,138-151` uses the number of existing attempts plus one and does not reject failure to create a fresh directory. With only `attempt-2` present, the next selected name is again `attempt-2`; session/plan are overwritten and raw/host rows appended. This can occur when a record collection is copied incompletely, and concurrent launches can also select the same name. Required change: choose a number above the maximum existing suffix, refuse an existing destination, and check successful exclusive directory creation before any writes. Demonstrate preservation of an existing noncontiguous attempt and refusal of an occupied destination. The reproduction here exercised the allocation arithmetic, not the runner.

**F5 — Medium: affinity observations are joined across snapshots by PID alone.** `host.ps1:18-27` obtains affinity using `Get-Process`, then obtains identity/creation time using a separate CIM enumeration, associating them only by PID. If a process exits and its PID is reused between enumerations, its replacement receives the predecessor's mask. `host.R:45-55` correctly checks parent creation ordering, but cannot detect this earlier identity mismatch. Required change: associate each affinity observation with that process object's creation time and require agreement with the CIM process identity; fail closed on an unavailable or changed identity on the measured chain. Add a mocked reuse case. This finding is a source-derived race scenario, not a claim that live PID reuse was observed.

**F6 — Medium: protocol/work validation silently accepts invalid inputs.** `protocol.R:77-82` casts before checking integrality: a protocol declaring **8.9** pairs is accepted as eight with no problems. `check.R:162-165` accepts every work field being `NA` because there is only one unique value; this corruption exits **0**. `measure.R:55-59` also marks a missing-valued work string successful. Required change: validate a finite integral pair count before conversion; require one nonmissing, nonblank work string per successful row before checking invariance. Workload-specific expected counts/statuses belong in `workloads.R` and must fail there when unmet; do not impose a generic positive trade-count rule. Add both negative demonstrations.

**F7 — Medium: the maintained rendered manual omits the new policy.** `inst/design/manual/benchmark_methodology.md:4-5` still advertises v0.2.0.1 and has no new regression-gate section. The manual landing page links that rendered file (`manual/README.md:45`) and explicitly requires committing both forms after source changes (`:53-65`). Required change: render and commit this article's Markdown sibling from the corrected QMD, reviewing the generated diff. Also clarify `benchmark_methodology.qmd:234-243`: the implemented checks enforce plan, affinity and foreign-R rules; closing other background applications remains a maintainer prerequisite, rather than something this probe verifies. Preserve that prerequisite and the accepted observation-only CPU policy. The rendered twin is outside the submitted change range; this is a missing companion artifact, not a request to edit it in this review.

2. **Arms:** `runner.R:64-65,91-107` resolves commit refs, archives each commit and checks `R CMD INSTALL` success into separate per-process temporary libraries.
