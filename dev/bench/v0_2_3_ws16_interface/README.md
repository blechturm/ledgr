# LDG-3211 interface probes, 2026-11-06

Evidence for the first-checkpoint interface table
(`inst/design/ledgr_v0_2_3_spec_packet/lean_core_interface.md`). Both probes
run on the pinned source tree `d5b3a151` (`git archive`, loaded with
`pkgload`) and refuse any other tree. They wrap pinned functions from
outside; nothing in `R/` changes. The shared helpers and workloads come from
`../v0_2_3_ws16_entry/`.

```sh
Rscript field_probe.R --pkg=<pinned source tree> --out=<dir>
Rscript tile_probe.R --pkg=<pinned source tree> --out=<dir>
```

| Probe | Question | Evidence |
| --- | --- | --- |
| `field_probe.R` | Which `services` fields and fold-state slots does each stage read and write, including through helpers? Which `services` fields change during a run? | `field_reads_by_stage.csv`, `services_mutability.csv`, `field_probe_workloads.csv` |
| `tile_probe.R` | Which stored planes do preparation, the fold reader and the history reads touch, at what index shape, and what full-axis outputs do they allocate? | `tile_access_by_site.csv` |

`field_probe.R` runs the eight A0 workloads, the 40 x 504 momentum run and
the 500 x 1,260 fill-heavy run. Each stage's `services` list becomes a
logging list, and its fold state a pass-through environment of active
bindings. The `via` column is the innermost ledgr function on the stack at
the access; for a lazily evaluated argument that is where the argument was
forced. Arguments passed on but never forced do not appear; the interface
table adds them from the static inventory
(`../v0_2_3_ws16_entry/evidence/stage_fields_static.csv`). Mutability
hashes each field's full serialization at the fold's first stage call and
when the fold returns. The JIT is off, so byte compilation does not change a
hash; `rlang::hash()` alone hashes environments by identity.

`tile_probe.R` runs the WS42 public-history fixture
(`tests/testthat/helper-history-fixtures.R` of the pinned tree: a late-known
lifetime fact, a bar gap and price carry) with one read of each public
request shape on every decided pulse. It also runs the 40 x 504 momentum run
with a 252-session feature window and an `Inf` bar read on its month-start
pulses.

The raw per-access logs (`field_reads_dynamic.csv`, `tile_access_log.csv`)
are regenerated by the probes and not committed. All data is simulated.
